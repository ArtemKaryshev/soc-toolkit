# Сценарии работы

## 1. Фишинговое письмо

Пользователь переслал подозрительное письмо, или почтовый шлюз выдал алерт.

1. **IOC → Извлечение:** загрузите `.eml` (пример: `samples/phishing.eml`).
   Появится панель «Разбор письма»: отправитель, Reply-To, Return-Path, SPF/DKIM/DMARC и вложения с хэшами.
   Предупреждения подсвечивают типовые признаки: Reply-To на другой домен, провал SPF/DMARC,
   вложение `.docm`/`.iso`/`.lnk`.
2. В таблице индикаторов видны URL и домены из письма (в том числе из HTML-ссылок) и хэши вложений.
   Строки с тегом `decoded` найдены внутри закодированных фрагментов, например в макросе.
3. **→ В репутацию:** внешние индикаторы переносятся на страницу проверки.
4. **Запросы:** шаблон «Письма от отправителя или с темой» показывает, кому ещё пришло письмо,
   «Обращения через прокси к домену» показывает, кто перешёл по ссылке.
5. **Разбор алерта → Вердикт и отчёт:** категория «Фишинг» подставит рекомендации
   (удалить письма, заблокировать отправителя, сбросить пароль кликнувшим).

## 2. Подбор пароля / RDP

1. Вставьте алерт KUMA (пример: «Пример: KUMA»). В хронологии видны 4625, затем 4624 с того же адреса.
2. Справочник → EventID 4625: таблица NTSTATUS поможет понять SubStatus.
3. Запросы «Успешный вход после серии неудачных» и «Входы по RDP» уже содержат пользователя и хост из алерта.
4. Проверьте внешний IP в репутации: AbuseIPDB и GreyNoise покажут, массовый ли это сканер.
5. Если успешный вход был, это True Positive с эскалацией.

## 3. Подозрительный PowerShell

1. Вставьте алерт Splunk (пример: «Пример: Splunk»). В командной строке есть `-enc`.
2. **IOC → Декодер:** вставьте командную строку и увидите исходный скрипт и IOC внутри
   (C2-адрес из `DownloadString`).
3. MITRE: T1059.001, а родитель WINWORD.EXE даёт T1204.002 и наводит на фишинговое вложение.
4. Запросы «Офисные приложения запускают оболочки» и «Процессы, подключавшиеся к IP» покажут масштаб.

## 4. Работа в TryHackMe SOC Simulator

Поля отчёта совпадают с формой симулятора. Удобный порядок:

1. Скопируйте данные алерта в JSON (или соберите вручную: `{"rule_name": "...", "host": "...", ...}`).
2. Разберите алерт, проверьте индикаторы, выберите вердикт.
3. Вкладка «Текст для копирования» содержит готовый Markdown, разделы которого вставляются в поля формы.
4. Сохраните кейс, чтобы потом найти повторяющиеся индикаторы в следующих алертах.

## 5. Командная строка в пайплайне

```bash
# индикаторы из всех логов папки в один STIX-файл
cat logs/*.log | soc-toolkit ioc extract - -f stix --external > bundle.json

# отчёт без интерфейса
soc-toolkit report alert.json -v FP -r "Плановое сканирование Nessus" -c generic -f html -o fp.html
```
