# Изменения

## 1.1.0 — 2026-10-31

- **Рекомендация по алерту** (`triage`): вердикт TP/FP с уверенностью, решение об эскалации и его причина.
  Около 40 признаков атаки и легитимной работы с весами, структурные признаки (4625→4624, офис → оболочка,
  индикаторы в раскодированной команде), репутация, решение из SIEM, исход (заблокировано/выполнено).
  Эскалация не предлагается, если атака заблокирована или не достигла цели; кража учётных данных,
  шифровальщик, перемещение и выгрузка эскалируются всегда.
- Все блоки отчёта строятся по оценке: признаки списком с найденными фрагментами, «против этого вывода»,
  причина эскалации или почему она не нужна, рекомендации с конкретными хостами, учётками и адресами.
- Разбор алертов: NDJSON, несколько объектов подряд, висячие запятые, Python-словари, CEF, key=value,
  Windows XML и текст журнала Windows; раскрытие вложенного JSON в `_raw`/`ExtendedProperties`;
  форматы Wazuh, QRadar, Sentinel, CrowdStrike; приоритет полей (process.name больше не становится
  названием алерта); шкала Wazuh rule.level; склейка короткого имени хоста и FQDN.
- CLI: команда `triage`, в `report` вердикт, категория и эскалация по умолчанию берутся из рекомендации.
- Примеры: Defender (заблокировано, без эскалации), Wazuh (SCCM, False Positive).
- 196 тестов.

## 1.0.1 — 2026-10-29

- Черновик «Reason for Classifying as TP/FP» и «Reason for Escalating» строится по уликам алерта:
  время, хосты, пользователи, признаки техник, цепочка 4625→4624, раскодированная команда PowerShell,
  внешние IOC и их репутация. В интерфейсе поля заполняются сами, в CLI подставляются, если `--reason`
  не указан. В отчёте больше нет «не указано».
- Новый пример `samples/alert_phishing.json` и кнопка «Пример: фишинг».
- Пример KUMA переделан в реалистичный подбор пароля: 8 неудачных входов и 1 успешный.
- Эвристики MITRE: SPF/DMARC fail → T1566, переход по ссылке → T1204.001.
- 158 тестов.

## 1.0.0 — 2026-10-29

Первая полноценная версия.

- Разбор алертов Splunk, KUMA, Elastic ECS, Defender и произвольного JSON: сущности, хронология,
  MITRE ATT&CK (явные и эвристические), параметры для запросов.
- Извлечение IOC: 14 типов, refang/defang, декодирование base64/PowerShell/URL-encoding, allowlist,
  разбор .eml (SPF/DKIM/DMARC, вложения), экспорт CSV/JSON/STIX 2.1.
- Репутация: VirusTotal, AbuseIPDB, OTX, GreyNoise, Shodan InternetDB, URLhaus; кеш, лимиты, повторы,
  параллельность, сводный вердикт, политика отправки.
- 34 шаблона запросов Splunk SPL и KUMA SQL в YAML, свои шаблоны.
- Отчёты RU/EN по шаблону TryHackMe: Markdown, HTML, DOCX; свои шаблоны Jinja2.
- Справочник: ATT&CK Enterprise (706 техник, 178 групп), LOLBAS (245), 110 EventID, таблицы кодов;
  обновление из интернета.
- История кейсов в SQLite: поиск, статусы, статистика, повторяющиеся IOC.
- Веб-интерфейс из 7 страниц и CLI.
- 144 теста, покрытие ядра 88%, ruff, mypy, CI на Windows и Linux, Docker, run.bat/run.sh.
